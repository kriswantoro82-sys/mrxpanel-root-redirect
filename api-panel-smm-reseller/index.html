API Panel SMM untuk Reseller: Cara Integrasi Website dengan Aman

Sudah memiliki website panel SMM dan ingin memakai katalog MRXPANEL sebagai penyedia layanan? Integrasi API dapat membantu membaca layanan, mengecek saldo, membuat pesanan, dan memantau status tanpa berpindah dashboard. Namun, integrasi perlu dirancang agar kunci rahasia terlindungi dan pesanan pelanggan tidak tercatat dua kali.

Mulai dari sini: gunakan Pusat API MRXPANEL sebagai sumber dokumentasi dan pengelolaan kunci resmi. Panduan ini menjelaskan persiapan dan praktik aman; contoh pembacaan data di bawah tidak membuat pesanan atau memotong saldo.

1. Apakah website reseller Anda perlu API?

API berguna jika website reseller sudah memiliki sistem pesanan sendiri dan perlu mengambil informasi dari MRXPANEL. Jika baru mencoba layanan secara manual, dashboard member biasanya lebih sederhana: daftar akun, baca katalog, lalu buat pesanan melalui antarmuka yang tersedia.

Untuk pemula, pahami dahulu dasar usaha reseller panel SMM dan cara menggunakan panel SMM. Integrasi tidak menggantikan kewajiban membaca deskripsi, harga, batas jumlah, dan ketentuan setiap layanan.

2. Pilih API sesuai sistem website

MRXPANEL menyediakan dua bentuk integrasi dengan format yang berbeda. Jangan mencampur parameter dan metode autentikasinya.

PilihanDipakai untuk
API SMM standar V2
https://api.mrxpanel.com/api/v2		Panel yang memiliki menu Providers / Add Provider. Menggunakan POST, format application/x-www-form-urlencoded, dengan parameter key dan action.
API JSON V1
https://api.mrxpanel.com/v1/		Website atau aplikasi kustom. Menggunakan JSON pada operasi yang sesuai dan header Authorization: Bearer API_KEY.

Keduanya adalah URL resmi yang tercantum dalam dokumentasi Pusat API. Untuk website yang meminta URL provider SMM standar, gunakan URL V2—bukan alamat dashboard atau URL layanan database internal.

3. Siapkan API Key dengan izin minimum

  1. Masuk ke Member MRXPANEL, kemudian buka Pusat API.
  2. Periksa daftar layanan dan kebutuhan website reseller terlebih dahulu.
  3. Buat API Key yang hanya memiliki izin yang diperlukan. Untuk pengujian baca-saja, cukup gunakan izin services:read dan balance:read.
  4. Aktifkan izin orders:create hanya jika sistem pesanan benar-benar siap. Izin ini dapat digunakan untuk membuat pesanan yang memakai saldo.
  5. Simpan kunci di server/backend dan batasi aksesnya. Jangan menaruh API Key dalam HTML publik, JavaScript browser, repository terbuka, atau pesan dukungan.

API Key baru hanya ditampilkan sekali saat dibuat. Kelola dan simpan kunci sesuai petunjuk pada dashboard resmi; bila ada keraguan setelah permintaan pembuatan kunci, periksa daftar kunci lebih dahulu daripada membuat banyak kunci sekaligus.

4. Uji koneksi tanpa membuat pesanan

Untuk API standar SMM, dua aksi yang sesuai untuk pemeriksaan awal adalah services (daftar layanan) dan balance (saldo). Contoh curl berikut hanya membaca informasi akun bila menggunakan kunci dengan izin yang sesuai:

Cek daftar layanan 
curl -X POST "https://api.mrxpanel.com/api/v2" \
  --data-urlencode "key=API_KEY_ANDA" \
  --data-urlencode "action=services"
Cek saldo 
curl -X POST "https://api.mrxpanel.com/api/v2" \
  --data-urlencode "key=API_KEY_ANDA" \
  --data-urlencode "action=balance"

Ganti placeholder API Key hanya pada perangkat/server yang Anda kendalikan. Jangan menempelkan kunci asli ke halaman publik. Contoh ini tidak dijalankan oleh website MRXPANEL.

Pusat API juga menyediakan tombol Uji Koneksi Website Reseller yang dirancang membaca daftar layanan dan saldo, tanpa membuat pesanan. Gunakan fasilitas itu terlebih dahulu sebelum mengaktifkan sistem transaksi otomatis.

5. Mencegah pesanan ganda saat jaringan bermasalah

Ini bagian yang sering terlewat ketika website reseller disambungkan ke penyedia. Jika permintaan membuat pesanan mengalami timeout, tidak berarti pesanan pasti gagal. Permintaan mungkin sudah diterima tetapi responsnya tidak sampai ke website.

  • Catat ID pesanan pelanggan di database reseller sebelum mengirim permintaan ke provider.
  • Jika software mendukungnya, berikan satu request_id yang stabil untuk satu pesanan pada API SMM V2.
  • Jangan membuat request_id baru hanya karena proses koneksi timeout.
  • Jangan menjalankan auto-retry untuk action=add tanpa pemeriksaan riwayat dan status terlebih dahulu.
  • Dokumentasi MRXPANEL menyatakan bahwa tanpa request_id, pencegahan permintaan identik hanya berlaku dalam jendela 30 detik. Pengiriman ulang setelah itu bisa menciptakan pesanan dan pemotongan saldo baru.
Ilustrasi operasional: pelanggan membuat pesanan #RES-2041, tetapi sistem reseller tidak menerima respons. Tandai pesanan sebagai menunggu verifikasi, cek riwayat serta saldo, dan cari nomor order yang mungkin sudah tercatat. Jangan langsung mengirim permintaan membuat pesanan kedua.

6. Pantau pesanan, refill, dan pembatalan dengan benar

API standar memiliki aksi status untuk memeriksa pesanan melalui parameter order, serta hingga 100 pesanan melalui orders. Simpan hubungan nomor order MRXPANEL dengan nomor pesanan pelanggan di sistem reseller Anda.

Dokumentasi MRXPANEL juga menjelaskan action_check untuk pemeriksaan kelayakan refill/cancel tanpa menghubungi provider. Ini berbeda dari mengajukan tindakan. Permintaan refill atau cancel dapat masuk antrean peninjauan; nomor permintaan bukan bukti bahwa provider sudah melakukan refill, pembatalan, atau refund. Jangan menampilkan status sukses sebelum ada konfirmasi hasil akhir.

7. Checklist sebelum integrasi dipakai pelanggan

  1. API URL dan format request sudah cocok dengan jenis integrasi.
  2. API Key aman di backend dan izinnya tidak berlebihan.
  3. Daftar layanan dan saldo dapat dibaca dengan benar; mata uang yang digunakan adalah IDR.
  4. Website reseller memakai ID layanan dari katalog API aktif, bukan menebak kode.
  5. Harga jual telah mempertimbangkan biaya layanan serta margin, dan diperiksa lagi jika katalog berubah.
  6. Sistem menyimpan ID pesanan pelanggan, nomor order provider, dan status terbaru.
  7. Pengiriman ulang pesanan saat timeout diblokir sampai riwayat diverifikasi.
  8. Dukungan pelanggan memahami perbedaan status pesanan, refill, cancel, dan refund.

Sebelum mengaktifkan harga otomatis pada website reseller, hitung biaya layanan dan biaya pembayaran agar target laba tidak terlewat. Gunakan kalkulator harga jual dan laba bersih reseller sebagai simulasi; sinkronkan harga aktual melalui katalog API resmi.

8. Pertanyaan umum

Apakah harus punya website reseller?

Tidak. API relevan bagi sistem yang ingin membuat integrasi otomatis. Pengguna tanpa website dapat mengakses layanan melalui dashboard member resmi.

Apakah pengujian API akan memotong saldo?

Permintaan baca-saja seperti services dan balance tidak membuat pesanan. Sebaliknya, action=add merupakan tindakan membuat pesanan dan dapat menggunakan saldo.

Apakah saldo API memakai rupiah?

Dokumentasi standar SMM MRXPANEL mencantumkan mata uang IDR. Website reseller perlu mendukung mata uang dan format harga yang sesuai.

Bagaimana jika panel saya tidak mendukung request_id?

Jangan mengandalkan retry otomatis. Catat status pengiriman, periksa pesanan dan saldo bila respons tidak pasti, lalu buat pesanan baru hanya setelah jelas pesanan sebelumnya tidak tercatat.

Siap menghubungkan website reseller?

Periksa URL API terbaru, izin API Key, contoh request, serta aturan transaksi langsung dari dokumentasi yang dipelihara oleh MRXPANEL.
